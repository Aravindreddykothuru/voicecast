# CosyVoice2 (TTS_PROVIDER=real) ONLY. Installed into its own venv/image,
# never into the same environment as requirements-ml.txt.
#
# Why: CosyVoice2 pins torch==2.3.1 / numpy==1.26.4. pyannote.audio +
# transformers (requirements-ml.txt, used by diarization/ASR/emotion/
# translation) pin torch==2.4.1 / numpy==2.5.3. Both sets were verified
# working in isolation; installed together, pip's resolver either fails
# outright or silently downgrades one stack until an unrelated stage breaks
# at runtime with no clear error pointing at the real cause. Locally this is
# `.venv-tts`, a second interpreter entirely; in Docker it is this file, its
# own Dockerfile.worker-tts, and the `worker-tts` compose service consuming
# only `q.synthesize`. See CONTRACTS.md #1 and README "Running with real
# models".
#
# Install order matters: requirements.txt (the app itself) first, then this
# file, then CosyVoice from source (see Dockerfile.worker-tts) -- CosyVoice's
# own requirements.txt additionally pulls deepspeed/tensorrt/gradio/grpc for
# its training and web-demo tooling, none of which inference through this
# provider's Python API needs, so they're deliberately left out here. Pins
# below are the exact subset verified to load CosyVoice2-0.5B and produce
# real audio (see app/providers/tts/cosyvoice_provider.py).
